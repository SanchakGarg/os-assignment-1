Who is who

Customers
One party per order. Party size = chairs needed (SPACE_REQ). Shirt colour = the order's colour, used everywhere.
Sign over a party
Chair icon + number = chairs needed side by side; table icon + number = tables needed side by side.
Outside
The memory queue (first in, first out). Only the head of the line, next to the door, is tried; if it doesn't fit, everyone behind it waits.
Waiting chairs
The SPACE pool, in the bottom-left corner. A party sits on chairs next to each other. Yellow dashed boxes = free gaps, green box = the gap the allocator chose.
Tables T1–T3
The TABLE pool. A table with the order's cloth and flag belongs to it. When the food is ready the party walks to its table, then leaves. 0 tables = takeaway (a paper bag from the counter).
Order board
The ready queue, in the order the scheduler will pick. The highlighted line on each ticket is what the scheduler looks at.
Chefs
The 2 CPUs. The bubble shows the order being cooked and its progress. A chef walks to a machine while the order uses it.
Machines
Shared resources, one user at a time. Light: green = free, red = in use, grey = not in this scenario. The badge shows the holder.
Red WAIT tags
Orders blocked waiting for that machine, first in line on top. They keep their chairs, tables and anything they hold.
Wall clock
The hand sweeps once per clock cycle.

    ALL FOUR CONDITIONS HOLD
    
      
      
        
    • Mutual exclusion: each machine serves one order at a time.
      • 
        
    • Hold and wait: each order keeps one machine while it waits for another.
      • 
        
    • No preemption: a machine is never taken away from its holder.
      • 
        
    • Circular wait: the orders wait for each other in a circle (above).
      • 
      
    
      
    The server found the cycle in the wait-for graph, stopped every worker thread and ended the run. With prevention ON, an order that asks for a lower-ranked machine while holding a higher one gives it back first (ROLLBACK), so the circle can never close.
